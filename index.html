At a glance

My work sits where product engineering, QA, and AI reliability meet.

The recurring theme across my repositories and upstream work is simple: a passing result is only useful when the system can explain what was actually measured.

01 — TEST ARCHITECTURE

Cross-layer verification

I build test strategies that put each assertion at the right source of truth instead of forcing everything through the UI. Browser behavior, API contracts, database state, native navigation, webhooks, and rendered pixels each get their own evidence layer.

Playwright · pytest · OpenAPI · PostgreSQL · Appium/Maestro · OpenCV
02 — AI RELIABILITY

Evaluation that fails honestly

I audit LLM and agent evaluation paths for cases where missing data, partial scoring, or unevaluated behavior can look like success. I prefer keyless reproducers, explicit contracts, regression tests, and fail-closed semantics.

Inspect AI · agent runtimes · evaluators · guardrails · decision contracts
03 — DELIVERY DISCIPLINE

Evidence before confidence

I use AI-assisted engineering, but I do not treat generated code or a green rerun as proof. Changes are tied to executable acceptance criteria, source-of-truth documents, regression evidence, and checks that are designed to fail when the claim is false.

GitHub Actions · CI gates · deterministic fixtures · mutation/revert checks · documented baselines

How I work

The method matters because reliability claims are easy to make and surprisingly easy to fake by accident.

Reproduce before fixing.Reduce the failure to something deterministic and explain the control case.
Assert durable truth.Use the API, database, rendered pixels, or runtime state when UI messaging is not authoritative.
Prove the test has teeth.Revert or mutate the fix and confirm the new regression test actually fails.
Separate observation from conclusion.A clean rerun is evidence; it is not automatically proof that the underlying race or defect is gone.
Make drift visible.Prefer semantic contracts, explicit ownership, pinned baselines, and mechanized checks over tribal knowledge.
Use AI, keep accountability.AI can accelerate implementation and investigation; executable evidence remains the authority.

What I’m aiming at

I’m interested in engineering roles and collaborations where correctness is not just “the tests are green,” but a system of evidence: AI/LLM evaluation, agent reliability, test architecture, QA automation, developer tooling, and product delivery where failure modes need to be understood rather than hidden.
